BookTalk 프로젝트의 JWT 인증 코드를 분석하다가 문제점을 발견하고 수정했다

---

### 문제 발견 — /api/member/me가 토큰 만료 시 204를 반환

`AuthContext`는 앱 마운트 시 `/api/member/me`를 호출해서 로그인 상태를 확인한다

```typescript
const fetchMember = async () => {
    try {
        const { status, data } = await apiClient.get('/api/member/me');
        setMember(status === 204 ? null : data);
    } catch {
        setMember(null);
    }
};
```

- **비로그인** → 204 → `setMember(null)`
- **로그인** → 200 + 회원 정보 → `setMember(data)`

그런데 **Access Token이 만료된 경우**에도 204가 반환되고 있었다

원인은 `JwtAuthenticationFilter`의 WHITELIST였다

```java
private static final List<String> WHITELIST = List.of(
    "/", "/error", "/api", "/login", "/oauth2"
);
```

`/api/member/me`는 `/api`로 시작하기 때문에 필터가 아예 스킵됐다

토큰이 만료돼도 필터를 거치지 않고 컨트롤러로 바로 가고, `authentication`이 null로 들어와서 204가 반환되는 것이었다

---

### 문제 — 토큰 만료인데 비로그인과 구분이 안 됨

Axios 인터셉터는 401을 감지해서 refresh를 시도한다

```typescript
if (error.response?.status === 401 && !originalRequest._retry) {
    originalRequest._retry = true;
    await apiClient.post('/api/auth/refresh');
    return apiClient(originalRequest);
}
```

그런데 `/api/member/me`가 토큰 만료 시 401이 아닌 204를 반환하니까 인터셉터가 동작하지 않았다

결과적으로 Access Token이 만료된 로그인 사용자가 앱에 진입하면 refresh 시도 없이 그냥 비로그인 처리가 됐다

---

### 수정 — WHITELIST에서 /api 제거, 개별 경로로 분리

```java
private static final List<String> WHITELIST = List.of(
    "/", "/error", "/login", "/oauth2",
    "/api/book", "/api/comment", "/api/auth"
);
```

`/api/member/me`를 WHITELIST에서 제외해서 필터를 타도록 했다

이제 토큰이 있는데 만료된 경우 필터에서 401을 반환한다

토큰이 아예 없는 비로그인은 필터의 `if (token != null)` 블록을 건너뛰고 컨트롤러까지 도달해서 204가 반환된다 — 정상 동작

---

### 인터셉터 — /api/member/me refresh 실패 처리

refresh 실패 시 기존 코드는 무조건 `/login`으로 이동했다

```typescript
} catch (refreshError) {
    window.location.href = '/login';
    return Promise.reject(refreshError);
}
```

그런데 `/api/member/me`는 비로그인도 접근하는 경로라 refresh 실패 시 강제 이동이 맞지 않는다

7일 후 재접속처럼 Refresh Token도 만료된 경우는 그냥 비로그인으로 처리하면 된다

```typescript
} catch (refreshError) {
    if (originalRequest.url !== '/api/member/me') {
        window.location.href = '/login';
    }
    return Promise.reject(refreshError);
}
```

### 최종 인증 흐름

**앱 진입 시**

```
/api/member/me 요청
├── 토큰 없음 (비로그인) → 필터 통과 → 204 → setMember(null)
├── 토큰 유효 → 필터 통과 → 200 + 회원 정보 → setMember(data)
└── 토큰 만료 → 필터에서 401
        └── 인터셉터 → refresh 시도
                ├── 성공 → /api/member/me 재시도 → setMember(data)
                └── 실패 (7일 경과) → setMember(null) → 비로그인 처리
```

**다른 요청에서 토큰 만료 시**

```
401 → 인터셉터 → refresh 시도
├── 성공 → 원래 요청 재시도
└── 실패 → /login 이동
```

---

### 기존에 /api/member/me를 예외로 뒀던 이유

원래 인터셉터에 이런 코드가 있었다

```typescript
if (originalRequest.url === '/api/member/me') {
    return Promise.reject(error);
}
```

비로그인 사용자가 401을 받았을 때 refresh → 실패 → `/login` 강제 이동되는 걸 막으려고 예외를 뒀던 것 같다

그런데 비로그인은 토큰 자체가 없어서 필터를 그냥 통과하고 204가 반환된다 — 401이 올 일이 없다

401이 왔다면 토큰은 있는데 만료된 경우니까 refresh를 시도하는 게 맞다

결국 예외 처리가 불필요했고, 오히려 토큰 만료 시 refresh를 막는 문제를 만들고 있었다
