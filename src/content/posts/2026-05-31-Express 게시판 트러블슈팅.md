생각보다 삽질을 좀 했다

---

### 문제 1. regdate, hit, replycount가 null

글을 쓰면 DB에 추가는 되는데 저 세 개가 null이었다

#### 원인

INSERT 쿼리에 그냥 안 넣었던 것

```ts
// 이렇게만 넣고 있었음
INSERT INTO board(name, subject, content, pwd) VALUES(?, ?, ?, ?)
```

#### 해결

```ts
INSERT INTO board(name, subject, content, pwd, regdate, hit, replycount)
VALUES(?, ?, ?, ?, NOW(), 0, 0)
```

단순한 실수였다

---

### 문제 2. 목록 조회가 빈 화면

API는 200으로 오고 데이터도 오는데 화면에 아무것도 안 떴다

#### 원인

프론트 TypeScript 인터페이스가 대문자로 되어 있었는데

```ts
interface BoardItem {
  NO: number;
  SUBJECT: string;
  NAME: string;
  DBDAY: string;
  HIT: number;
}
```

MySQL은 `SELECT no, subject`처럼 소문자로 쓰면 소문자로 반환한다

그래서 `board.NO`가 전부 `undefined`였던 것

MySQL은 SELECT 절에 쓴 이름 그대로 반환하고

테이블 컬럼이 소문자로 정의돼 있으면 대문자로 써도 소문자로 온다

#### 해결

```ts
SELECT no AS NO, subject AS SUBJECT, name AS NAME,
       DATE_FORMAT(regdate, '%Y-%m-%d') AS DBDAY, hit AS HIT
FROM board
```

AS로 대문자 alias를 줬다

### 문제 3. 비밀번호 틀려도 수정/삭제가 됨

어떤 비밀번호를 입력해도 수정/삭제가 통과됐다

#### 원인

```ts
const [check] = await db.execute(checkSql, [no, pwd]);
const count = (check as any[])[0] ?? 0;  // {cnt: 0} 객체
if (count === 0) { ... }  // 객체 === 0 → 항상 false
```

`execute`가 반환하는 `rows[0]`은 `{cnt: 0}` 객체인데

그걸 숫자 `0`이랑 비교하고 있었던 것

당연히 항상 `false`라 검증이 항상 통과됐다

#### 해결

```ts
const count = (check as any[])[0]?.cnt ?? 0;
if (count === 0) { ... }
```

`.cnt`로 꺼내서 비교했다

### 마무리

목록 빈 화면 문제가 원인 찾기 제일 까다로웠다

응답 데이터를 콘솔로 찍어보고 나서야 키가 소문자로 오고 있다는 걸 알았다
