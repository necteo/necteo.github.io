프로젝트를 마무리하고 배포를 했는데

사용자 위치를 가져오는 Geolocation API가 거부되는 상황이 발생했다

큰 일이 났음을 직감한 나는 곧바로 검색을 시작했는데

Geolocation같은 API는 https에서만 작동한다고 한다 ㄱ-

그리하여 허겁지겁 AWS 서버를 1시간안에 https가 가능하게 만들어야 했는데...

### 1단계: 자체 서명 인증서 생성 (임시)

```bash
# 1. 디렉토리 생성
sudo mkdir -p /etc/ssl/private

# 2. 자체 서명 인증서 생성
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/selfsigned.key \
  -out /etc/ssl/certs/selfsigned.crt \
  -subj "/C=KR/ST=Seoul/L=Seoul/O=MyCompany/OU=IT/CN=임시인증서/emailAddress=admin@example.com"

# 3. 권한 설정
sudo chmod 600 /etc/ssl/private/selfsigned.key
sudo chmod 644 /etc/ssl/certs/selfsigned.crt
```

### 2단계: Nginx 기본 설정

```bash
# 1. 기존 설정 백업
sudo cp /etc/nginx/sites-available/default /etc/nginx/sites-available/default.backup

# 2. 설정 파일 편집
sudo nano /etc/nginx/sites-available/default
```

**전체 내용을 아래로 교체:**

```nginx
# HTTP → HTTPS 리다이렉트
server {
  listen 80;
  listen [::]:80;
  server_name _;  # 임시로 모든 도메인 허용
  return 301 https://$host$request_uri;
}

# HTTPS 설정
server {
  listen 443 ssl;
  listen [::]:443 ssl;
  server_name _;

  # 임시 자체 서명 인증서 (나중에 Certbot이 자동 수정)
  ssl_certificate /etc/ssl/certs/selfsigned.crt;
  ssl_certificate_key /etc/ssl/private/selfsigned.key;

  # SSL 프로토콜 설정
  ssl_protocols TLSv1.2 TLSv1.3;
  ssl_ciphers HIGH:!aNULL:!MD5;
  ssl_prefer_server_ciphers on;

  # Spring Boot 프록시 설정
  location / {
    proxy_pass http://localhost:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Port $server_port;
  }

  # WebSocket 지원 (주문 실시간 알림)
  location /ws {
    proxy_pass http://localhost:8000/ws;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # 로그 파일
  access_log /var/log/nginx/access.log;
  error_log /var/log/nginx/error.log;
}
```

```bash
# 3. 문법 검사
sudo nginx -t

# 예상 출력:
# nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
# nginx: configuration file /etc/nginx/nginx.conf test is successful

# 4. Nginx 재시작
sudo systemctl restart nginx

# 5. 상태 확인
sudo systemctl status nginx
```

### 3단계: DuckDNS 도메인 생성

**웹 브라우저에서:**

1. https://www.duckdns.org 접속
2. GitHub, Google 등으로 로그인
3. 도메인 이름 입력 (예: sist-all-movie)

- 결과: sist-all-movie.duckdns.org

4. current ip에 서버 IP 입력 (예: 54.147.137.211)
5. "update ip" 버튼 클릭

**DNS 전파 확인** (1~2분 소요)



```nginx
http {
    # ... 기존 설정

    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;

               application/json application/javascript
               application/xml+rss application/rss+xml
```
